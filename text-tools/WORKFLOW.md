# 포트폴리오 텍스트 벌크 편집 워크플로우

`drmoony.github.io`(EN/KO 이중언어 단일 페이지)의 **모든 화면 텍스트**를 한 파일로 뽑아
사람이 벌크로 첨삭하고, 그 변화만 `index.html`에 정확히 되돌려 넣는 파이프라인.

> 핵심 원칙: **텍스트만 바뀐다.** 레이아웃·클래스·태그 구조·요소 순서는 건드리지 않는다.
> 사람은 글자만 고치고, 스크립트는 바뀐 글자만 원래 자리에 끼워 넣는다.

---

## 왜 이런 구조인가

이 사이트는 한 요소를 EN/KO 두 벌로 담아 두고 CSS로 언어를 토글한다.

```html
<span class="lx-en">Competencies</span><span class="lx-ko">역량 지도</span>
```

```css
body.lang-ko .lx-en{display:none!important;}
body:not(.lang-ko) .lx-ko{display:none!important;}
```

- 텍스트가 `lx-en` / `lx-ko` 클래스를 단 `<p>`·`<span>` 안에 흩어져 있고(255쌍),
- 일부는 `<em>`, `<b class="dot">·</b>` 같은 **인라인 태그**와 `&amp;` **엔티티**를 품고 있으며,
- 마퀴(흐르는 배너)는 같은 문구를 `aria-hidden` 사본으로 한 번 더 갖는다.

그래서 "찾아 바꾸기"로는 위험하다(부분 문자열 충돌, 태그 훼손, 사본 누락).
→ **바이트 오프셋 기반 splice**로 각 요소를 정확히 특정해 교체한다.

---

## 파일 구성 (`text-tools/`)

| 파일 | 역할 | 편집 |
|------|------|------|
| `extract.py` | `index.html` → 편집 시트 + 매핑 생성 | 코드 |
| `apply.py` | 편집 시트 → `index.html` 반영 | 코드 |
| `portfolio_text.txt` | **사람이 편집하는 시트** (EN/KO 페어 255개) | ✍️ 여기만 |
| `portfolio_map.json` | id ↔ 바이트 오프셋 매핑 (기계용) | ✕ 건드리지 말 것 |

---

## 3단계 흐름

```
┌─ 1. 추출 ──────────┐   ┌─ 2. 사람 편집 ──────┐   ┌─ 3. 반영 ──────────┐
│ python3            │   │ portfolio_text.txt  │   │ python3            │
│  text-tools/       │──▶│ 탭 뒤 글자만 수정   │──▶│  text-tools/       │
│  extract.py        │   │ (태그·엔티티 보존)  │   │  apply.py [파일]   │
└────────────────────┘   └─────────────────────┘   └────────────────────┘
        │                                                    │
   portfolio_text.txt                              바뀐 요소만 offset splice
   portfolio_map.json                              + aria 사본 동기화
```

### 1) 추출

```bash
python3 text-tools/extract.py
```

`portfolio_text.txt`를 생성한다. 형식:

```
[001]
EN	Competencies
KO	역량 지도

[002]
EN	Selected work
KO	주요 작업
```

- `[NNN]` = 안정적인 문서 순번 id
- `EN` / `KO` 뒤는 **탭 1개**, 그다음이 요소의 inner HTML 그대로

### 2) 사람 편집 (규칙)

두 가지 방법 — **(a) 텍스트 직접 편집** 또는 **(b) 윤문 에디터(권장)**.

**(a) txt 직접 편집**
- `[NNN]` 헤더와 `EN` / `KO` **접두어 + 탭**은 그대로 둔다.
- **탭 뒤 텍스트만** 고친다.
- `<em>...</em>`, `<b class="dot">·</b>` 같은 **태그**와 `&amp;` **엔티티**는 그대로 두고 글자만 바꾼다.
- 안 고칠 항목은 그대로 둔다 — 스크립트가 **바뀐 것만** 감지한다.
- 줄을 추가·삭제하거나 순서를 바꾸지 않는다(항목 개수가 달라지면 반영 거부).

**(b) 윤문 에디터 — `text-tools/editor.html`** (자체 완결 HTML, 브라우저에서 열기)
- `portfolio_text.txt`를 붙여넣고 **EN/KO 시트로 불러오기** → 항목마다 **원문(읽기전용) + 편집 박스**.
- 편집 박스에서 **문체만** 고치면 **글자 단위 diff**(빨강 삭제·초록 추가)로 변경점을 바로 보여줌
  — 작업자·의뢰자 모두 무엇이 바뀌었는지 확인. 변경량 %·수정 항목 수 집계.
- **시트로 내보내기** → `portfolio_text.edited.txt` (아래 3단계 `apply.py`로 그대로 반영).
- **변경 리포트**(before→after)·**편집본 복사**도 지원. 편집 내용은 브라우저에 자동 저장.
- 일반 텍스트(줄/문단)도 지원 — CV 등 다른 문안 윤문에도 재사용.

### 3) 반영

```bash
python3 text-tools/apply.py                              # 기본 시트 반영
python3 text-tools/apply.py portfolio_text.edited.txt    # 에디터가 내보낸 시트 반영
python3 text-tools/apply.py portfolio_text.edited.txt --dry   # 미리보기(파일 미수정)
```

에디터(2b)의 **시트로 내보내기** 결과 `portfolio_text.edited.txt`를 그대로 넘기면 된다
(맨 위 주석 줄은 자동 무시). id 기준으로 **바뀐 항목만** 오프셋 splice.

`--dry`로 diff를 먼저 확인한 뒤 실제 반영을 권장한다.

## 안전장치 (apply.py가 보장하는 것)

1. **오프셋 splice** — 각 요소를 바이트 위치로 특정. 같은 문구가 여러 곳에 있어도,
   한 문구가 다른 문구의 부분 문자열이어도 오작동하지 않는다.
2. **바뀐 것만 반영** — 원문 inner와 시트 값을 비교해 다른 항목만 교체.
3. **아래→위 순서 적용** — 뒤쪽부터 splice해서 앞쪽 오프셋이 어긋나지 않게 한다.
4. **aria 사본 동기화** — 마퀴의 `aria-hidden` 쌍도 같은 원문이면 함께 갱신.
5. **태그 구성 변화 경고** — 편집 중 태그가 빠지거나 추가되면 `⚠`로 알리고 old/new를 보여준다.
6. **항목 수 불일치 시 중단** — 시트 id 개수 ≠ html 페어 개수면 반영을 거부(줄 추가/삭제 방지).

---

## 매핑이 깨지지 않는 이유

- `extract.py`는 결정적(deterministic)이다. **같은 `index.html` → 같은 id·오프셋.**
- `apply.py`는 반영 직전 `index.html`을 **다시 추출**해 신선한 오프셋을 얻는다.
  → 시트를 만든 시점과 반영 시점 사이에 다른 편집만 없으면 항상 정확히 맞는다.
- 페어링은 "k번째 EN ↔ k번째 KO"(문서 순서 스트림 인덱스). 전 구간 정렬 검증됨(255=255).
  work-detail 블록이 DOM에서 `EN들 → KO들` 순으로 그룹핑돼 있어 **인접 페어링은 쓰지 않는다.**

---

## 재추출이 필요한 때

`index.html`의 **구조**(요소 추가/삭제/순서 변경)를 바꾸면 기존 시트의 id가 어긋난다.
그럴 땐 `extract.py`를 다시 돌려 새 시트를 받고 편집을 이어간다. 단순 텍스트 편집만
반복할 때는 재추출 없이 같은 시트를 계속 써도 된다.

---

## 한 줄 요약

> `extract.py`로 뽑고 → 탭 뒤 글자만 고치고 → `apply.py`로 되돌린다.
> 오프셋·id 기반이라 순서·중복·태그 걱정 없이 **텍스트 변화만** 그대로 반영된다.
